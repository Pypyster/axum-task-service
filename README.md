# 📘 axum-task-service

Сервис управления задачами, разработанный на **Rust**, **Axum** и **PostgreSQL**.

Проект реализует REST API для регистрации пользователей, JWT-аутентификации и управления задачами с ролевой моделью доступа. Приложение разделено на слои работы с базой данных, HTTP-обработчики, структуры данных и middleware авторизации.

## 🚀 Возможности

- Регистрация пользователей
- Аутентификация через JWT
- Хеширование паролей с помощью bcrypt
- Роли пользователей: `admin` и `user`
- Управление задачами:
  - создание задачи — только для admin
  - получение списка задач
  - получение задачи по ID
  - обновление статуса собственной задачи — для user
  - полное обновление задачи — только для admin
  - удаление задачи — только для admin
- Управление пользователями — только для admin
- Разграничение доступа на основе JWT claims
- Каскадное удаление задач при удалении пользователя

## 🔐 Аутентификация

После успешного входа сервер создаёт JWT-токен. Токен содержит claims:

```json
{
  "sub": 1,
  "role": "user",
  "exp": 1788709404
}
```

Где:

| Claim | Значение |
|---|---|
| `sub` | ID пользователя |
| `role` | Роль пользователя: `user` или `admin` |
| `exp` | Unix timestamp окончания срока действия токена |

Для защищённых endpoint-ов токен передаётся в заголовке:

```http
Authorization: Bearer <JWT_TOKEN>
```

Middleware выполняет следующие действия:

1. Извлекает токен из заголовка `Authorization`
2. Проверяет подпись JWT
3. Проверяет срок действия `exp`
4. Декодирует `Claims`
5. Добавляет `Claims` в `request.extensions`
6. Передаёт запрос нужному handler-у

## 👥 Роли и права

### 👤 User

Обычный пользователь может:

- Получить список только своих задач
- Получить конкретную задачу, если она принадлежит ему
- Изменить только статус собственной задачи

Обычный пользователь не может:

- Создавать задачи
- Удалять задачи
- Изменять название задачи
- Полностью обновлять задачу
- Изменять чужие задачи
- Получать список пользователей
- Получать пользователя по ID или телефону
- Удалять пользователей

### 🛡 Admin

Администратор может:

- Создавать задачи для любого пользователя
- Получать список всех задач
- Получать любую задачу по ID
- Полностью обновлять задачу: `name` и `status`
- Удалять задачи
- Получать список всех пользователей
- Получать пользователя по ID
- Получать пользователя по номеру телефона
- Удалять пользователей

## 📌 Логика доступа к задачам

|---|:---:|:---:|

| Получить конкретную задачу | Только свою | Любую |

| Удалить задачу | ❌ | ✅ |

## 🧱 Архитектура

Проект разделён на несколько логических уровней.

### PostgreSQL

База данных содержит таблицы:

- `users`
- `tasks`

Таблица `tasks` содержит поле `user_id`, которое связывает задачу с пользователем.

Пример связи:

```text
users.id
   │
   └── tasks.user_id
```

При удалении пользователя PostgreSQL удаляет связанные задачи через внешний ключ с правилом:

```sql
ON DELETE CASCADE
```

Это означает:

```text
Удаление пользователя
        ↓
Удаление всех задач пользователя
```

Удаление задачи удаляет только соответствующую запись из таблицы `tasks`.

### `db/`

Папка `db/` содержит функции работы с PostgreSQL:

- создание таблиц
- создание пользователей
- поиск пользователей
- создание задач
- получение задач
- обновление задач
- удаление задач

Функции этого слоя не зависят от Axum и HTTP-запросов.

### `handlers/`

Папка `handlers/` содержит HTTP-обработчики:

- `users.rs` — регистрация, вход и операции с пользователями
- `tasks.rs` — операции с задачами
- `auth.rs` — создание и проверка JWT, auth middleware, admin middleware
- `routes.rs` — описание HTTP-маршрутов приложения

Handlers:

1. Принимают HTTP-запрос
2. Извлекают JSON, path-параметры, состояние БД и claims
3. Проверяют права пользователя
4. Вызывают функции из `db/`
5. Формируют HTTP-ответ

### `structs/`

Папка `structs/` содержит структуры данных:

- модели пользователей
- модели задач
- DTO запросов и ответов
- `Claims` для JWT
- `UserRole`
- перечисления статусов задач

## ⚙️ Конфигурация

Создай файл `.env` в корне проекта:

```env
DATABASE_URL=postgres://postgres:password@localhost:5432/task_db
JWT_SECRET=replace-with-a-long-random-secret
```

Где:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL |
| `JWT_SECRET` | Секрет для подписи и проверки JWT |

Пример `.env.example`:

```env
DATABASE_URL=postgres://postgres:password@localhost:5432/task_db
JWT_SECRET=change-this-secret-in-production
```

## ▶️ Запуск проекта

1. Установи PostgreSQL и создай базу данных:

```sql
CREATE DATABASE task_db;
```

2. Создай `.env` на основе `.env.example`.

3. Запусти сервер:

```bash
cargo run
```

После запуска сервер будет доступен по адресу:

```text
http://localhost:3000
```

## 🌐 API Маршруты

### Публичные маршруты

| Метод | Endpoint | Описание |
|---|---|---|
| `POST` | `/register` | Регистрация пользователя |
| `POST` | `/login` | Вход и получение JWT |

### Маршруты задач

| Метод | Endpoint | Описание |
|---|---|---|
| `GET` | `/tasks` | Получить задачи: свои для user, все для admin |
| `POST` | `/tasks` | Создать задачу, только admin |
| `GET` | `/tasks/{id}` | Получить задачу по ID |
| `PUT` | `/tasks/{id}` | Обновить задачу |
| `DELETE` | `/tasks/{id}` | Удалить задачу, только admin |

### Маршруты пользователей

Все маршруты пользователей доступны только admin.

| Метод | Endpoint | Описание |
|---|---|---|
| `GET` | `/users` | Получить всех пользователей |
| `GET` | `/users/id/{id}` | Получить пользователя по ID |
| `GET` | `/users/phone/{phone}` | Получить пользователя по телефону |
| `DELETE` | `/users/id/{id}` | Удалить пользователя по ID |
| `DELETE` | `/users/phone/{phone}` | Удалить пользователя по телефону |

## 🧪 Тестирование API

Для ручной проверки API можно использовать файл:

```text
requests.http
```

Файл поддерживается расширением REST Client в VS Code или HTTP Client в JetBrains IDE.

Пример защищённого запроса:

```http
GET http://localhost:3000/tasks
Authorization: Bearer <JWT_TOKEN>
```

## 🔒 Безопасность

- Пароли не хранятся в открытом виде
- В базе данных сохраняются bcrypt-хеши паролей
- JWT подписываются секретом `JWT_SECRET`
- JWT имеют ограниченный срок действия через claim `exp`
- Доступ к ресурсам проверяется по роли пользователя
- Пользователь не может получить, изменить или удалить чужие задачи
- Публичная регистрация не должна позволять пользователю самостоятельно назначать роль `admin`
